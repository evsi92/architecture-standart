### <a name="_qmphm5d6rvi3"></a>**Решение**
Так как решение ограниченно технически, самым простым вариантом будет обмен данных через письма. 
Со стороны банка письмо будет отправлять автоматически раз в день с актуальными данными, которые ранее уже были обработаны и предоставлены сотрудниками бэк-офиса. 
Необходима доработка нового сервиса с агрегированными данными. Помимо его обязанности предоставлять аналогичные данные через api, Компонент будет отправлять письмо по расписанию. 
Также доработка потребуется на стороне кол-центра. Так как есть необходимость во время пиковой нагрузки подключать кол-центр партнера, то данные должны быть выгружены из письма и загружены в систему, которую используют основной кол-центр и партнерский
Загрузка данных будет осуществляться вручную сотрудником кол-центра. 
Необходима доработка на стороне ПО кол-центра: необходим endpoint, который будет принимать файл и раскладывать данные в систему. 

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

- Отправка актуальных данных через API. Тогда у банка всегда есть подтверждение о принятии и о соответствии формата отправляемых данных, плюс отсутствие мануальных действий сотрудника
- Асинхронная передача данных через очередь сообщений - возможность обновлять данные в режиме реального времени
- Не загружать данные из письма в систему. Но в этом случае партнерский кол-центр не будет иметь доступ к данным, а также сотрудникам кол-центра не будет удобно использовать данные

**Недостатки, ограничения, риски**

- Риски связанные с безопасностью. На данный момент митигируется тем, что не предоставляется персонализированная информация, а лишь анонимизированная общая статистика на данный день
- Риск недоставки данных. Если письмо не дошло или сотрудник не сделал выгрузку, у сотрудников кол-центра нет актуальных данных для работы с клиентами
- Риски несовместимости данных. Если произойдут коллизии на стороне банка и файл поменяет формат, то его не смогут загрузить в систему кол-центра
